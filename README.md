# Topaz password manager

WARNING: this is experimental code written mostly for my own entertainment, and
it has not been properly tested or vetted. Use at your own risk.

## Usage

Generate a new password by running
```
$ topaz -a example.com
Creating new account example.com. If you mistyped the name, exit with Ctrl-C and try again.
Please type the domain password: ****************************
Type password again to confirm: **************************** 
affront legwork specks overbook unlikable moneybags
```

You can have more than one domain password; different passwords simply generate
different results. You could, for example, use one domain for a few more
sensitive passwords and another domain for more numerous accounts.

Note: **Your domain password(s) should be difficult to brute-force.** See
"Security considerations" below.

Later, you can type the same account name and the same domain password to get
the same password again:

```
$ topaz -a example.com
Please type the domain password: ****************************
Type password again to confirm: **************************** 
affront legwork specks overbook unlikable moneybags
```

One nice feature of topaz is that this works *even if you enter the password the
second time on a totally different machine*, no syncing required.

If the service asking you to make a password has stupid requirements like
maximum length, mixing upper- and lowercase letters, or including numbers and
symbols, you can pass `--stupid` to get a version of the password that is
designed to meet those requirements.

```
$ topaz -a example.com --stupid
Please type the domain password: ****************************
Type password again to confirm: **************************** 
AffLegSpeOveUnlMon1! 
```

You can also generate completely random passwords with `-r`. Topaz will not
remember these, so you need to write them down or store them somewhere yourself
if you want to retrieve them later.

```
$ topaz -r
appease overcook coliseum lapdog unreached reversing
```

## Design

The basic idea is to take a "domain password" and then hash it along with a
counter and the name of the service you're creating a password for, then use the
hash as a seed to index into a long list of memorable words:

The general goals motivating the design include:

- available across devices without transfer of secrets
- passwords are feasible to memorize
- multiple domains for different passwords
- doesn't use a ton of computational resources

The hash used is SHA512/256. No, that is not a specialized password-based hash
or key derivation function, thanks for asking. Those algorithms spend a ton of
resources to compute the hash in order to make brute force attacks difficult
even for weak passwords. Topaz is designed to be more computationally
lightweight, so it leans on the assumption that the domain password is not
garbage in order to use a normal hash. Don"t pick a garbage domain password.

The attack scenarios topaz considers include:

- an attacker gets access to an unlocked laptop with topaz installed and tries
  to genenerate passwords for different accounts
- an attacker gets access to some generated passwords via phishing or a data
  breach and tries to use these to guess passwords generated by topaz for the
  same user's other accounts

Other forms of attack such as side channel attacks with locally installed
malware are not in scope.

## Security considerations

**Domain password(s) should be difficult to brute-force.** If an attacker learns
one of the generated passwords, they can spend as much time as they like trying
to guess your domain password. If they guess it, they can guess all your
generated passwords in that domain.

Your domain passwords should not be related to each other (e.g. prefixes of one
another), especially if one of them is weaker than the other. An attacker who
manages to guess a weaker domain password could potentially try to check a
smaller search space of related values for other domain passwords.

Passwords generated with topaz have about 77 bits of entropy by default
(assuming the domain password has at least that much, otherwise it's the minimum
of the two). This means it should take an attacker about 2^77 tries to
brute-force them. The parameter is selected to balance security with password
memorability; more words or more obscure words would increase security, and a
lower security threshold would result in fewer words per password. You can
adjust topaz's security threshold or change the word list that it uses if you
have different preferences.
